Use this page for an Expo app. This is the recommended install for most apps.

This module contains custom native code. Expo Go cannot run it. You use a
[development build](https://docs.expo.dev/develop/development-builds/introduction/), usually with
`expo-dev-client` or
[Expo Application Services (EAS) Build](https://docs.expo.dev/build/introduction/).

A bare React Native CLI project uses [Install with React Native CLI](/installation/react-native).

## 1. Install the package

```bash
npx expo install react-native-google-mobile-ads
```

## 2. Configure your app IDs (config plugin)

Add the Expo config plugin to `app.json`, `app.config.js`, or `app.config.ts`. After you change it, rebuild native code and install the new build on your device. The steps are in [Generate native projects](#4-generate-native-projects-prebuild).

Before you display ads, create a [Google AdMob account](https://apps.admob.com) and an app ID for each platform. [Configuration](/configuration) shows where the app ID appears in AdMob.

```json
// <project-root>/app.json
{
  "expo": {
    "plugins": [
      [
        "react-native-google-mobile-ads",
        {
          "androidAppId": "ca-app-pub-xxxxxxxx~xxxxxxxx",
          "iosAppId": "ca-app-pub-xxxxxxxx~xxxxxxxx"
        }
      ]
    ]
  }
}
```

Every plugin key is on the [Config plugin](/config-plugin) page.

<Info>
  Put Expo app IDs on the config plugin only. You do not also add a root-level
  `react-native-google-mobile-ads` block with `ios_app_id` or `android_app_id`. The plugin writes
  `GADApplicationIdentifier` and the Android `APPLICATION_ID` during prebuild. A legacy build-script
  warning about a missing root `ios_app_id` or `android_app_id` can still appear. Ignore that warning
  when the plugin already wrote the IDs.
</Info>

## 3. Add a development client

If you do not already have a development build workflow, install the Expo development client:

```bash
npx expo install expo-dev-client
```

Then create a development build. Use EAS, or a local prebuild and a `run:*` command, in the next section.

## 4. Generate native projects (prebuild)

After you install the module or change the plugin config, generate the native projects, then build each platform:

```bash
npx expo prebuild

# iOS
npx expo run:ios

# Android
npx expo run:android
```

If you use EAS instead of a local `run:*` command, create a new development build. EAS runs prebuild as part of the build:

```bash
npm install --global eas-cli

# Online
eas build --profile development

# Local
eas build --profile development --local
```

Run prebuild again, or create a new EAS build, when you change app IDs or other plugin options.

## App Tracking Transparency (iOS)

Apple requires the app to show the App Tracking Transparency authorization request before it reads the Identifier for Advertisers. The person using the app chooses personalized or non-personalized ads. In the project configuration file, set a user tracking usage description:

```json
// <project-root>/app.json
{
  "expo": {
    "plugins": [
      [
        "react-native-google-mobile-ads",
        {
          "androidAppId": "ca-app-pub-xxxxxxxx~xxxxxxxx",
          "iosAppId": "ca-app-pub-xxxxxxxx~xxxxxxxx",
          "userTrackingUsageDescription": "This identifier will be used to deliver personalized ads to you."
        }
      ]
    ]
  }
}
```

Request authorization at runtime on the [Consent and privacy](/consent-basics) page.

## Optionally configure iOS static frameworks

This module does not require static frameworks for a normal Expo install. Use them only when another dependency needs `use_frameworks! :linkage => :static`.

<Warning>
  React Native Firebase coexistence is on the [React Native Firebase](/firebase) page. Use that page's dynamic Podfile and static ads pod. Do not use the static snippet on this page as the React Native Firebase recipe. Static frameworks alone fail at `pod install` when React Native Firebase uses its default Swift Package Manager (SPM) mode.
</Warning>

On Expo, enable fully static frameworks for the whole Podfile with `expo-build-properties` only when another dependency, unrelated to React Native Firebase, needs that mode. For React Native Firebase with SPM, you still set `$RNGoogleMobileAdsAsStaticFramework = true` in the generated Podfile, as the React Native Firebase page describes. If a resource-bundle pod fails on `IPHONEOS_DEPLOYMENT_TARGET`, follow [iOS CocoaPods deployment targets](/prerequisites#ios-cocoapods-deployment-targets). Merge the plugin entry from the [`expo-build-properties` instructions](https://docs.expo.dev/versions/latest/sdk/build-properties/):

```json
// <project-root>/app.json
{
  "expo": {
    "plugins": [
      [
        "expo-build-properties",
        {
          "ios": {
            "useFrameworks": "static"
          }
        }
      ]
    ]
  }
}
```
