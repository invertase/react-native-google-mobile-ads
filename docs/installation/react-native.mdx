---
title: Install with React Native CLI
description: Autolinking and app.json app IDs for a bare React Native app.
---

Use this if your app does not use [Expo](https://expo.dev/). Your React Native CLI project is already a native iOS and Android app, so there is no config plugin and no prebuild step.

The library autolinks. Put the AdMob app IDs in the root `app.json`, using snake_case. Do not paste IDs into `Info.plist` or `AndroidManifest.xml`, and do not edit `AppDelegate` or `MainApplication` for a standard install.

If your app uses Expo, follow [Install with Expo](/installation/expo).

<Steps>
  <Step title="Install the package">
    ```bash
    npm install react-native-google-mobile-ads
    ```
  </Step>
  <Step title="Configure your app IDs">
    Before you display ads, create a [Google AdMob account](https://apps.admob.com) and an app ID for each platform. [Google AdMob](/configuration) shows where the app ID appears in AdMob.

    Add the IDs under the top-level `react-native-google-mobile-ads` key in the project-root `app.json`, using snake_case. Autolinking and the Android Gradle and iOS config scripts apply these values during the native build. Edit this JSON, then rebuild. Do not keep a second copy in the native project files.

    ```json
    // <project-root>/app.json
    {
      "react-native-google-mobile-ads": {
        "android_app_id": "ca-app-pub-xxxxxxxx~xxxxxxxx",
        "ios_app_id": "ca-app-pub-xxxxxxxx~xxxxxxxx"
      }
    }
    ```

    <Warning>
      If `android_app_id` or `ios_app_id` is missing from that block, native build scripts warn and the
      Google Mobile Ads software development kit (SDK) can crash on startup. An Expo app that sets IDs only on the config plugin can
      ignore that warning. [Install with Expo](/installation/expo) covers that path.
    </Warning>

    The [Config plugin](/config-plugin) page lists every key, including the Expo camelCase names.
  </Step>
  <Step title="Rebuild the app">
    ```bash
    # For iOS
    npx pod-install
    npx react-native run-ios

    # For Android
    npx react-native run-android
    ```
  </Step>
</Steps>

## iOS packaging and frameworks (CocoaPods)

This module is a CocoaPods pod only. There is no Swift Package Manager (SPM) `Package.swift` distribution yet. Until an SPM package exists, integrate the module through CocoaPods. Expo prebuild and Continuous Native Generation still resolve native modules through CocoaPods.

By default the podspec sets `static_framework` to `false`. Under CocoaPods `use_frameworks!`, the module uses dynamic linkage unless you opt into static frameworks in the next section. That default matches `use_frameworks! :linkage => :dynamic`. It does not replace a future SPM package for apps that consume React Native Firebase, or other dependencies, through SPM only.

### Optionally configure iOS static frameworks

This module does not require static frameworks for a normal bare install. Use them only when another dependency needs `use_frameworks! :linkage => :static` in your `Podfile`, for a need unrelated to React Native Firebase.

<Warning>
  React Native Firebase coexistence is on the [React Native Firebase](/firebase) page. Use that page's dynamic Podfile and static ads pod. Do not switch the whole Podfile to static frameworks as a substitute.
</Warning>

On a bare app, when you enable static frameworks, set `$RNGoogleMobileAdsAsStaticFramework = true` in the `Podfile` before any target block, `use_native_modules!`, or `use_react_native!`. Then run `pod install` again. Expo sets the same flag with `expo-build-properties` on [Install with Expo](/installation/expo#optionally-configure-ios-static-frameworks).

```ruby
$RNGoogleMobileAdsAsStaticFramework = true
```

## App Tracking Transparency (iOS)

Apple requires the app to show the App Tracking Transparency authorization request before it reads the Identifier for Advertisers. The person using the app chooses personalized or non-personalized ads. In the project configuration file, set a user tracking usage description:

```json
// <project-root>/app.json
{
  "react-native-google-mobile-ads": {
    "android_app_id": "ca-app-pub-xxxxxxxx~xxxxxxxx",
    "ios_app_id": "ca-app-pub-xxxxxxxx~xxxxxxxx",
    "user_tracking_usage_description": "This identifier will be used to deliver personalized ads to you."
  }
}
```

Request authorization at runtime on the [Consent and privacy](/consent-basics) page.

## iOS app ID build phase (`ios_config.sh`)

CocoaPods installs an Xcode build phase named `[RNGoogleMobileAds] Configuration`. That phase writes `GADApplicationIdentifier` into the built app `Info.plist` from `app.json`.

If a release build fails with `unable to locate Info.plist`, upgrade this package and run `pod install` again so the embedded `ios_config.sh` polls briefly for `$(BUILT_PRODUCTS_DIR)/$(INFOPLIST_PATH)` before it fails. Xcode can start the phase before Process Info.plist finishes writing that file. Phase timing metadata alone is not enough. Do not move that script earlier in Build Phases. An Expo app that uses the config plugin sets the app ID at prebuild and does not use this build phase.
