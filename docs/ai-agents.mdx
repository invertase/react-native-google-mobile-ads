Copy this prompt into your coding agent. It follows the path from prerequisites through a test ad.

```text
Read https://docs.page/invertase/react-native-google-mobile-ads/prerequisites.md, then https://docs.page/invertase/react-native-google-mobile-ads/installation/expo.md (use …/installation/react-native.md for bare RN CLI), then https://docs.page/invertase/react-native-google-mobile-ads/consent-basics.md, https://docs.page/invertase/react-native-google-mobile-ads/initialization.md, and https://docs.page/invertase/react-native-google-mobile-ads/first-ad.md. After install, read node_modules/react-native-google-mobile-ads/AGENTS.md. React Native 0.86 or newer. New Architecture required. Consent before initialize. Test ad units until the integration is verified.
```

That block is the install step. Paste it, then let the agent run. Native Google skills, Report issues, and Maintainer knowledge bundle are the rules the block does not include.

## Native Google skills

Google publishes agent skills for the native Google Mobile Ads software development kits (SDKs). This library is a React Native layer over those SDKs, so a native skill does not always match this interface. The npm `AGENTS.md` file lists those skills, how to install them, and which ones not to apply. If a native skill and this library disagree, follow these docs and the package types.

## Report issues

When you file an issue on the [GitHub repository](https://github.com/invertase/react-native-google-mobile-ads), include a minimal reproduction and the details in [Diagnostics dump for issue reports](/migration/v17#diagnostics-dump-for-issue-reports). To rule out configuration causes, use [Ad Inspector](/ad-inspector) and [Configuration failures](/common-reasons-for-ads-not-showing) first.

## Maintainer knowledge bundle

The repository keeps a maintainer knowledge bundle under the `okf-bundle/` directory on [GitHub](https://github.com/invertase/react-native-google-mobile-ads/tree/main/okf-bundle). It covers architecture decisions, testing, and continuous integration (CI) workflows for people working on the library. Integrators do not need it.
